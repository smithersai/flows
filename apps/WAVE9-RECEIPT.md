## What changed

### One page: the chat (will's ruling, 2026-08-09 — law)

- **`src/mainview/LandingSurface.tsx` deleted**, and with it the `gated` branch in `App.tsx` that swapped the root surface. Session state changes what the chat CONTAINS, never which page exists.
- **`src/mainview/App.tsx`** — a derived `authMessage` (a projection of the identity record, never stored state) opens the transcript exactly while a definitive gated answer holds:
  - *Signed-out:* "Smithers is a design-partner preview — sign in with GitHub to continue." plus the plain-words scopes copy (the wave-7/8 copy, unchanged), with **Sign in with GitHub** riding the message (`data-command="auth.sign-in"`, autofocused — first-Tab reachable; the composer yields autofocus in this state).
  - *Signed-in, not allowlisted:* the honest closed-alpha state; **Request access** rides the message (`auth.request-access`); `auth.sign-out` stays reachable via `/` (the message says so). After requesting, the message states the waiting state with no dead button; a failed request appends the honest error line.
- **Message actions:** `MessageSchema` gains an optional `action: { command, label }`; stored messages can carry one (dispatched via the extended `message.appended`), and the synthetic auth message renders through the same path — one rendering, one command binding.
- **Honestly gated composer:** signed-out / non-allowlisted placeholders name the one needed step; `send()` short-circuits BEFORE any backend call to a calm one-line Smithers reply carrying the same action (the user's draft is never eaten; slash commands still run, so `/auth.sign-in` works signed-out).
- **Failed OAuth return:** `AppController.handleAuthReturn(search)` consumes `?auth=failed|error` at boot (`main.tsx` strips the query after) and renders the honest line + a retry sign-in action as a chat message. Wave-8's branded HTML page is untouched and remains ONLY for the mid-redirect failure, where the browser is off-app; its back-home link lands in the chat, which now exists signed-out (live-checked).
- **`DESIGN.md`** records the law in §3 ("One page: the chat. Auth is a conversation state, not a view. A second page is a design defect.") plus the toast law and the free-chat ruling.

### Free interactive chat, UI half (will's ruling, 2026-08-09)

- **No per-turn dollar line:** the client-side usage read (`recordTurnCost`), the `message.cost.recorded` transition, the `costUsd` message field, and the "This turn cost $X" rendering are all gone. The true cost stays recorded by the billing seam (the wave-9b backend policy marks chat *complimentary*: cost recorded, zero debited — the landed `section-d-money.spec.ts` D-2/D-4 in flows/ui is that contract); the balance chip still refreshes from the real answer after every turn.
- **$0 never pauses chat:** the `billing.work.paused` transition and the composer/suggestion gating on `allowedToStartWork:false` are removed (the pause discipline now applies only to non-complimentary paid work, of which the app has none). The dollar chip stays, and a $0 balance states it once in the composer status line: "Balance: $0 — chat is on us during the alpha, so this conversation never pauses."

### The 300ms toast law (will's ruling, 2026-08-09)

- **One shared mechanism:** a persisted `toasts` TanStack DB collection (`toast.shown` / `toast.resolved` / `toast.dismissed` transitions through the one dispatcher, journaled with actors like everything else) rendered by **`src/mainview/ToastStack.tsx`** — a corner stack composed from `@smthrs/ui` `Alert`/`Spinner`/`Button`, not hand-rolled markup. Toasts are notifications, not state: a boot reconciliation dismisses any leftover toasts (a closed session's "running" notice never resurrects).
- **`withToast(key, runningTitle, doneTitle, work)`** in the controller: a 300ms debounce — work settling faster never flashes anything; past 300ms the toast states what is running, then **resolves into the result** — ok swaps the running sentence for the settled one ("Reading your repos…" → "Read your repos") and auto-dismisses, failed keeps the attempt's title with the honest detail under it and stays until dismissed through the registered hidden `toast.dismiss` command. One toast per flow key, with a run counter so a finished run never resolves or auto-dismisses the toast a newer run of the same flow is using. A flow that *throws* is caught and reported as an honest failure — the debounce is always cleared, so no toast can be stranded "running". Both the debounce and the auto-dismiss are injectable (`AppServices.toastDebounceMs` / `toastAutoDismissMs`) so tests pin every edge.
- **Applied to every background flow:** reco first-run/refresh ("Reading your repos…" — the trigger case), reco feedback posts, balance refresh, and every admin op (allowlist, grant, queue read/approve, feedback log, health).

## Review pass (post-landing, same run)

A review of the landed diff found four defects in the toast mechanism and the chat markup; all four are fixed in-tree, each with a regression test that fails without its fix (verified by reverting each fix in turn):

1. **A running toast could silently vanish.** The ok auto-dismiss timer fired on `toast-${key}` with no ownership check, so a second run of the same flow within the 4s window (e.g. the post-turn balance refresh on two quick turns) had its *running* notice deleted by the previous run's stale timer — the one thing the 300ms law exists to prevent. Fixed with a per-key run counter; a superseded run neither resolves nor dismisses the newer run's toast.
2. **A settled-ok toast never stated its result.** It kept the running sentence ("Refreshing your balance…") with the spinner gone for the four seconds before dismissal — it read as still running. `toast.resolved` now carries the settled title, and every call site supplies one.
3. **A throwing flow stranded a toast "running" forever.** `withToast` had no `try/finally`: a throw inside the work (e.g. `errorMessageOf` reading a body that fails, which sits outside the reco/admin try blocks) skipped `clearTimeout`, so the debounce still fired and nothing ever resolved it — and the rejection escaped a caller that never caught it. Now caught, cleared in `finally`, and reported as an honest failure line.
4. **Mangled JSX indentation** in `App.tsx` from the edit pass (the message-action block, the suggestion map, and the world `<section>` collapsed onto its ternary). Cosmetic only — reindented.
