# Wave 12 — Receipt: the claim surface stops being the model's

2026-08-10 (UTC) · run `oneshot-wave12-truth` · branch `oneshot-mskp7qe7-work` (~/mvp)

**Bottom line:** wave 11 tried to talk the model out of lying — an unmistakable tool result, an explicit system-prompt instruction, both pinned by test — and the deployed model wrote *"The workflow "summarize-open-issues" has been created and is now running"* beside a card that truthfully read *Running*. Wave 12 stops arguing. A run-launching command now answers a **minimal machine acknowledgment**, the act line is rendered from that acknowledgment, and any prose the model writes in the same turn as a launch is **held back and rendered only if it claims nothing about run state** — otherwise the client's own line stands in its place. The exact wave-11 transcript, replayed through the real controller *and* through the real Worker in the worker e2e, renders **"I started a create-workflow run — the run card shows its real progress."** and never *"has been created"*.

## 1. Result claims are deterministic (§1)

`src/mainview/state/RunClaims.ts` (new) is the whole rule, pure and unit-pinned:

- **`runLaunchCommandOf(toolName, toolArguments)`** — the model reaches the app through the one `commands` tool, so a launch is named inside its JSON arguments. `workflow.create` and `workflow.run` are the two.
- **`toolResultLaunchedRun(result)`** — only a REAL launch arms the substitution. A refusal, an unknown workflow, a chooser route launched nothing, so there is no run to misdescribe and the model's prose stands untouched. Suppressing there would be censorship, not truth.
- **`claimsRunState(text)`** — a run subject (`workflow`/`run`/`flow`/`it`/`that`…) beside a state word (`created`/`ready`/`running`/`done`/`shortly`…). Deliberately broad: a suppressed innocent sentence costs one deterministic line beside a truthful card; a missed claim is a lie on screen.
- **`renderedRunTurnText(command, modelText)`** — the model's words, or the client's line: *"I started a create-workflow run — the run card shows its real progress."* (The brief drafted that line as *"…the card below…"*; §7(5) is why it names the card instead of pointing at it.)

The controller applies it (`src/mainview/state/AppController.ts`):

- After a launch executes, the turn's text deltas are **buffered rather than rendered**, so a claim is never on screen even for the beat it would take to stream.
- On settle, the check reads the **whole answer** — anything streamed before the tool call plus everything withheld after it, because a preamble and a continuation land in one bubble and half-suppressing a claim still ships it. The substitution is a journaled transition (`message.claim.substituted`, actor `system`), not an invisible edit.
- The **tool result** is now `run-started workflow=create-workflow run=<id> repo=<owner/repo>` — a machine acknowledgment, nothing to round up from. The **act line** is rendered from it: *"Smithers started a create-workflow run on codeplanesmithers/smithers-demo"*.
- Belt and braces, the system prompt gained one line: after a run-launch the client REPLACES prose about run state, so narrating the run is not merely forbidden, it is discarded.

**The test asserts the rendered output, not the model's intent.** `src/mainview/state/Wave12.test.ts` replays the canary frames through the real controller: the transcript contains no `has been created`, no invented `summarize-open-issues`, and does contain the deterministic line and the act line. The worker e2e does the same through the **real Worker** with a stub model armed to emit that exact sentence.

## 2. `workflow.create` asks which watched repo (§2)

- A trailing `owner/repo` is the target and the rest is the description — one argument string, so the slash form and the agent tool get it identically (`splitDescriptionAndRepo`).
- With **more than one** watched repo and no argument, the `workflow-repo` card renders **embedded** (THE EMBED LAW), keyboard-complete (arrows move, Enter chooses), and **one act** answers it: choosing IS the confirm, and the create resumes on the repo named. Nothing is provisioned on a guess.
- **One watched repo is not a question.** A repo *outside* the watched set still routes to the wave-10 chooser, unchanged.

## 3. A run the workspace never finishes (§3)

After **10 minutes** with no event progress (injectable; the tests drive milliseconds), the card states plainly that the run has gone quiet and the pump **stops**. Progress resets the clock — new events, a cursor that advanced, or a run that *changed* what it says about itself; a `getRun` that keeps repeating `running` is not progress, which is precisely the state this exists for (wave 11's credential-less `create-workflow` run is exactly it).

The two acts are registered commands bound to the card's buttons: **`workflow.run.retry`** ("Check again") restarts the watch and says so in words, and **`workflow.run.stop`** ("Stop watching") settles the card to a `stopped` phase. Stop is stop *watching* — this seam relays no `cancelRun`, and claiming a cancellation would be the same kind of lie §1 is about. A stop landing mid-iteration can no longer be overwritten by an answer that was already in flight (found by the worker e2e, fixed with two `pump.stopped` guards).

## 6. Honest gaps

- **The live create→completed journey did not finish this session.** Smithers Cloud answers the provision route `HTTP 500: internal server error` — the same class of instability wave 11 recorded — so the gateway never reaches `ready` and there is no run card to follow. That is a seam outside this app; the product surfaces it as the honest failure and the check's zero-console-errors bar fails on the resulting 502, correctly. (The second half of this gap as originally written — "the reco seam is 401, so the watched set never loads and `workflow.create` **correctly** routes to the wave-10 chooser" — was wrong on the word *correctly*: the selection is durable and readable without GitHub, and the app was throwing it away. §7(8).)
- **Wave 11's launch blocker stands:** gateway VMs carry no AI-provider credential, so `create-workflow`'s agent nodes still die with *"OPENROUTER_API_KEY is not set"*. Nothing in this wave touches that, and "at least one flow created through conversation" still cannot be met.
- **The model frequently does not reach for the command at all.** Three of four live attempts answered with prose promising to open a chooser (once invoking `repos.watch` instead of `workflow.create`). §1 makes what it *says about a launch* deterministic; it does not make it *launch*. The "never announce an action without the tool call" instruction is still prompt-level, and still not holding.
- **The claim detector is blunt by construction.** A sentence that mentions a run and any state word is replaced, so a genuinely useful aside ("this run will need your approval at the PR step") can be swallowed. That is the trade the brief asked for; if it bites, the fix is a narrower subject/state pairing, not a return to trusting the prose.
- **Reasoning text is not post-processed.** The substitution replaces the ANSWER; a claim inside a visible reasoning block would survive. No live case has shown one, and rewriting reasoning would misrepresent what the model actually thought.
- **The quiet bound is client-side only.** A run that goes quiet is still running on the workspace as far as anyone knows; "stop" stops watching. Cancelling for real needs a `cancelRun` the relay allowlist does not carry.
- **A trailing `owner/repo`-shaped token is always read as the target.** `workflow.create a workflow that lints src/index.ts` takes `src/index.ts` for the repository and routes to the wave-10 chooser naming it. It is *stated*, never silent, and the alternative (accepting only watched repos) would break the "a repo outside the set opens the chooser" law — but the description is dropped and the user retypes. Left as the trade §2 asks for.
- **Signed out, "the whole transcript" means the seeded welcome, not history.** The §4 fix drops the welcome message; a session that EXPIRES mid-conversation still renders that conversation under the sign-in message. Hiding a user's own words would be its own defect, so this is the line drawn — but it is not literally "only the auth state", and the pinned test covers the seeded case only.

2. **A launch could brick the chat.** After a launch the model's text is *buffered*, so a continuation of nothing but whitespace left no answer message behind — `message.response.completed` no-ops without one, so the session's phase stayed `responding` and `send` refused every later submit, permanently. The blank case now reports itself through the empty-response path that already existed.
3. **A claiming preamble survived a stop.** The substitution ran only on the natural settle. 4. **A quiet run still glanced as Running.** §3's two new phases fell through `pillStatus` to `running`, so a card whose body read *"This run has gone quiet — … so I stopped checking"* wore a **Running** pill, and so did *"I stopped watching this run."* The pill is the most-read claim on a card. 5. **The deterministic line made a false claim about itself.** *"…the card below shows its real progress"* — the run card is minted during the tool call, so it renders **above** that line in the common path, and **below** it when the model streamed a preamble first (the message already exists at an earlier ordinal and the substitution edits it in place). 10. **The which-repo question could be answered twice.** Two clicks racing the card's state would have run `createWorkflow` twice — two real runs on the user's workspace. An answered card refuses politely.
