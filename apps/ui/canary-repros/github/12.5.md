# 12.5 — `/repos.app` never links to the fix

Origin: https://canary.smithers.sh · tested 2026-08-19 · account `codeplanesmithers`
Repro: `bun apps/ui/canary-repros/github/12.5.ts` · screenshot `/tmp/canary-github-12.5.png`

## Steps

1. Sign in on https://canary.smithers.sh as `codeplanesmithers`.
2. Type `/repos.app codeplanesmithers/canary-sandbox` and submit.

## Expected

The checklist row asks for two things: the App's real installation state, and a
link to the fix when it is not installed. `AppStatusSeam.checkGitHubApp` writes
`… Install it here: <url>` whenever the platform returns a trusted
`https://github.com/…` install URL.

## Actual

Only the first half. The transcript line is:

```
The Smithers GitHub App is not installed on codeplanesmithers/canary-sandbox, and the platform's install link wasn't usable.
```

No link is offered, on any of the three fixture repos
(`canary-sandbox`, `demo-calendar`, `smithers-demo`).

## Route and selector

- Flow: `repos.app` (`data-flow="repos.app"`), typed into `textarea.smithers-composer`.
- Route: `GET /api/repos/{owner}/{repo}/github-app-status`, which answers

```json
{"github_app_installed":false,"github_app_configured":false,"install_url":"","owner":"codeplanesmithers","repo":"canary-sandbox"}
```

## Root cause

`install_url` is empty because plue reports the App as *not configured*.
`githubAppInstallURL(configured)` in
`~/plue/internal/services/repo_connection_github_app.go` returns `""` whenever
`githubAppCredentialsConfigured()` is false, and that reads
`SMITHERS_GITHUB_APP_ID` + `SMITHERS_GITHUB_APP_PRIVATE_KEY` from the process
environment.

The `smithers-api` deployment in namespace `smithers` on
`gke_plue-prod-1771780303_us-central1_plue-cluster` sets neither. Its only
GitHub-related env vars are `SMITHERS_AUTH_GITHUB_CLIENT_ID`,
`SMITHERS_AUTH_GITHUB_CLIENT_SECRET`, `SMITHERS_AUTH_GITHUB_REDIRECT_URL` and
`SMITHERS_WEBHOOK_GITHUB_APP_SECRET`.

Secret Manager on `plue-prod-1771780303` already holds `plue-github-app-id` and
`plue-github-app-private-key`, so the App itself exists — only the wiring is
missing.

**Fix:** add `SMITHERS_GITHUB_APP_ID` and `SMITHERS_GITHUB_APP_PRIVATE_KEY` to
the `smithers-api` container env, sourced from those two secrets, and roll the
deployment. The UI half then needs no change: the seam already renders the link
as soon as the platform returns one.

This repro was NOT applied — a verifier does not mutate the prod deployment.
