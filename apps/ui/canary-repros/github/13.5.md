# 13.5 — the created issue is not on GitHub, and the card links to nothing

Origin: https://canary.smithers.sh · tested 2026-08-19 · account `codeplanesmithers`
Repro: `bun apps/ui/canary-repros/github/13.5.ts` · screenshot `/tmp/canary-github-13.5.png`

## Steps

1. Sign in on https://canary.smithers.sh.
2. Type `/issues.create canary repro 13.5 <stamp> codeplanesmithers/canary-sandbox`.
3. Read the resulting `[data-kind="issue"]` card, then look for the issue on
   github.com.

## Expected

"The created issue exists on GitHub and the card links to it."

## Actual

Both halves fail.

- The card carries **no anchors at all** (`card.locator("a")` → `[]`), so there
  is nothing to click through to.
- The issue exists only in the jjhub mirror (`api.jjhub.tech`). GitHub's search
  for the title returns `total_count: 0`, and the newest real issue on
  github.com/codeplanesmithers/canary-sandbox is still #149 from 2026-08-10.

The two number spaces also collide. The card renders
`Issue #43 · codeplanesmithers/canary-sandbox` for a mirror issue while
github.com's issue #43 in that same repository is an unrelated
`smithers-e2e disposable 1785901239544`. A card that names a repo and a number
reads as GitHub state it is not.

## Route and selector

- Flow: `issues.create`; card `[data-kind="issue"]`.
- Route: `POST /api/repos/{owner}/{repo}/issues` → the plue/jjhub platform,
  never `api.github.com`.
