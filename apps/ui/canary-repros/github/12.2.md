# 12.2 — a large-repo import never reaches a terminal state

Origin: https://canary.smithers.sh · tested 2026-08-19 · account `codeplanesmithers`
Repro: `bun apps/ui/canary-repros/github/12.2.ts` · screenshot `/tmp/canary-github-12.2.png`

## Steps

1. Sign in on https://canary.smithers.sh.
2. Type `/repos.import facebook/react` and submit.
3. Watch `[data-kind="repo-import"]`.

## Expected

"Progress is legible and the card ends in a terminal state" — DONE or FAILED.

## Actual

Progress copy is legible: the card walks `Contacting GitHub…` and (for smaller
repos) `Uploading to Smithers Cloud…`. It never terminates. After roughly two
minutes the progress line becomes

```
lost the import stream — run /repos.import again to re-check
```

while the status badge stays `RUNNING`. Observed unchanged at t+240s in the
repro, and at t+300s in a longer manual run.

Re-running `/repos.import facebook/react` does not help: it re-attaches to the
**same** job id and repeats the same stall.

Small repos are fine — `codeplanesmithers/demo-calendar` reaches DONE in about
four seconds, and `evmts/app` (no access) reaches FAILED in the same time.

## Route and selector

- Flow: `repos.import`; card `[data-kind="repo-import"]`.
- Routes: `POST /api/github/import` starts the job,
  `GET /api/github/import/{jobId}` polls it.

## Backend state

The job is wedged on the platform, not just in the UI:

```
GET /api/github/import/d8ff5a56-28f4-42a7-913a-ed3cdc219889
{"importJobId":"d8ff5a56-…","repoOwner":"codeplanesmithers","repoName":"react",
 "target_bookmark":"main","status":"cloning","stage":"resolving",
 "created_at":"2026-08-19T06:05:59.791236Z","updated_at":"2026-08-19T07:06:16.477917Z"}
```

It has been `cloning`/`resolving` for over an hour. `GET /api/repos/facebook/react`
answers `404 {"message":"repository not found"}` throughout.

Two distinct defects sit here:

1. The import worker does not finish (or time out) a large clone.
2. Even granting a slow backend, the card has no terminal state for "the stream
   is gone and the job stopped moving" — it stays `RUNNING` forever, so a user
   is never told the import failed.

Note also that the job renames the target: `facebook/react` is imported as
`codeplanesmithers/react`.
