# 13.3 — issue markdown renders, images do not

Origin: https://canary.smithers.sh · tested 2026-08-19 · account `codeplanesmithers`
Repro: `bun apps/ui/canary-repros/github/13.3.ts` · screenshot `/tmp/canary-github-13.3.png`

## Steps

1. Create an issue whose body and one comment each carry a markdown image
   (`![octocat](https://github.githubassets.com/…/Octocat.png)`). The repro
   script creates its own fixture through
   `POST /api/repos/{owner}/{repo}/issues` and `…/issues/{n}/comments`.
2. Type `/issues.view <n> codeplanesmithers/canary-sandbox` and submit.

## Expected

The row asks for "the body and comments, including markdown and images". Both
images render as `<img>`.

## Actual

Markdown renders correctly — `## Heading`, `**bold**`, `` `code` ``, fenced code
blocks (with Wrap/Copy), bullet and ordered lists, and links all come out right.
Images do not: the card contains **zero** `<img>` elements. `![alt](url)` is
emitted as a literal `!` followed by an ordinary link:

```html
<p class="sui-md-p">!<a class="sui-md-link" href="https://github.githubassets.com/images/modules/logos_page/Octocat.png">smithers octocat</a></p>
```

so the rendered text reads `!octocat` instead of showing the picture.

## Route and selector

- Flow: `issues.view`; card `[data-kind="issue"]`; markdown container
  `.smithers-card-markdown`, paragraph class `.sui-md-p`, link class
  `.sui-md-link`.
- Route: `GET /api/repos/{owner}/{repo}/issues/{n}` and `…/comments`.
- The markdown renderer has no image rule; the `!` is left as text and the
  bracket/paren pair is consumed by the link rule.
