# 19.2 — there is no unread indicator to clear

Origin: <https://canary.smithers.sh>  ·  Account: `codeplanesmithers`  ·  Tested: 2026-08-19

## Checklist row

> **19.2** `/notifications.read` marks every notification read, and the unread
> indicator clears.

## Fixture

Same seeded notification as 19.1 (jjhub `notifications` row id 1, `user_id = 9`,
reset to `status = 'unread'` before each run).

## Steps

1. Sign in on <https://canary.smithers.sh>.
2. Send `/notifications.list` with one UNREAD notification on the wire.
3. Look for the unread Badge, the `BellDot` icon, and the "Mark all read" button.
4. Send `/notifications.read`.

## Expected

The card shows the row as unread with a "Mark all read" button; running the
flow marks it read and the indicator clears.

## Actual

The server half works: `PUT /api/notifications/mark-read` answers **204** and
the platform row really does flip from `status: "unread"` to
`status: "read"` with a `read_at`.

The UI half does not exist. With one unread notification on the wire the card
renders `Nothing new.` — zero `[data-read="false"]` rows and zero
`[data-flow="notifications.read"]` affordances. Every unread indicator
(`Badge variant="outline">unread`, `BellDot`, the "Mark all read" button gated
on `payload.unread > 0`) hangs off list rows the seam dropped in 19.1, so the
indicator never appears and there is nothing for the flow to clear.

## Selectors and routes

- Routes: `GET /api/notifications/list?limit=20&all=true`, `PUT /api/notifications/mark-read`.
- Selectors: `[data-kind="notifications"] [data-read="false"]`, `[data-flow="notifications.read"]`.
- Source: `apps/ui/src/mainview/cards/NotificationsCard.tsx`, `.../seams/NotificationsSeam.ts`.
