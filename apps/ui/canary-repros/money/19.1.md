# 19.1 — a populated notifications list always renders as "Nothing new."

Origin: <https://canary.smithers.sh>  ·  Account: `codeplanesmithers`  ·  Tested: 2026-08-19

## Checklist row

> **19.1** `/notifications.list` renders the list, with an empty state.

## Fixture

The account had zero notifications, so the row could not be graded as written.
One was seeded against the prod jjhub database so a real list exists:

```

  exec <smithers-api pod> -c api -- bun -e '
    const {SQL} = require("bun"); const s = new SQL(process.env.SMITHERS_DATABASE_URL);
    await s`insert into notifications (user_id, source_type, source_id, subject, body)
            values (9, ${"issue"}, 1179, ${"canary money-lane fixture: ..."}, ${"..."})`;
    await s.end()'
```

`user_id = 9` is `codeplanesmithers`; `source_id = 1179` is a real issue in
repo 3503 (`codeplanesmithers/canary-sandbox`), which the reader must own for
`filterReadableNotifications` to let the row through. Row id `1` — delete it
when this is fixed.

## Steps

1. Sign in on <https://canary.smithers.sh>.
2. `fetch("/api/notifications/list?limit=20&all=true")` — confirm one row comes back.
3. Send `/notifications.list`.

## Expected

The notifications card lists the one notification.

## Actual

The platform answers one row:

```json
[{"id":1,"source_type":"issue","source_id":1179,
  "subject":"canary money-lane fixture: issue canary ui mrjwmjf9 needs you",
  "body":"…","status":"unread","read_at":null,"created_at":"2026-08-19T07:13:10Z"}]
```

The card renders `Notifications / DONE / notifications · 12:30 AM / Nothing new.`
— zero `.world-card-row` elements.

## Root cause

`parseNotification` in `apps/ui/src/mainview/state/seams/NotificationsSeam.ts`
parses the **GitHub notifications** wire shape:

- `subject.title` (object) — jjhub sends `subject` as a plain **string**
- `repository.full_name` — jjhub sends no repository object
- `unread: boolean` — jjhub sends `status: "unread" | "read"`

`title` therefore resolves to `null` for every jjhub row, `parseNotification`
returns `null`, and `parseNotificationList` drops it. The empty state is the
only state this seam can ever render against the real platform.

## Selectors and routes

- Route: `GET /api/notifications/list?limit=20&all=true`.
- Card: `[data-kind="notifications"]`, rows `.world-card-row`.
