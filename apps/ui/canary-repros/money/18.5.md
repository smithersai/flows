# 18.5 — `/keys.remove` for a provider with no key says nothing

Origin: <https://canary.smithers.sh>  ·  Account: `codeplanesmithers`  ·  Tested: 2026-08-19

## Checklist row

> **18.5** `/keys.remove` for a provider with no key.

## Steps

1. Sign in on <https://canary.smithers.sh>.
2. Send `/keys.remove gemini` (no such key on the account).
3. Send `/keys.remove` with no provider at all.

## Expected

Both are honest refusals the user can read: "there is no gemini key to remove",
and "keys.remove needs the provider name".

## Actual

Both are completely silent — no transcript line, no toast, no card.

- `/keys.remove gemini` issues `DELETE /api/user/byok-keys/gemini`, gets 404,
  and the page text does not change.
- `/keys.remove` with no argument issues **no request at all**. `KeysSeam.removeKey`
  returns the string `"keys.remove needs the provider name"`, and the composer
  path throws it away: `send` in `AppController.ts` calls
  `void commands.run(parsed.name, parsed.args)` with no
  `.then(surfaceCommandFailure)`, unlike `runCommand`/`runCommandArgs`.

## Selectors and routes

- Route: `DELETE /api/user/byok-keys/{provider}`.
- Source: `apps/ui/src/mainview/state/seams/KeysSeam.ts` (`removeKey`), `apps/ui/src/mainview/state/AppController.ts` (`send`, `surfaceCommandFailure`).
