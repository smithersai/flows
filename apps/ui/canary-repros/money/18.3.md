# 18.3 — `/keys.remove <provider>` cannot remove anything

Origin: <https://canary.smithers.sh>  ·  Account: `codeplanesmithers`  ·  Tested: 2026-08-19

## Checklist row

> **18.3** `/keys.remove <provider>` removes it and the change survives a reload.

## Steps

1. Sign in on <https://canary.smithers.sh>.
2. Send `/keys.remove anthropic`.
3. Reload, send `/keys.list`.

## Expected

The provider's key is removed, the keys card re-lists without it, and the
removal is still gone after a reload.

## Actual

`DELETE /api/user/byok-keys/anthropic` answers **404 `404 page not found`** —
the jjhub platform has no BYOK route (see 18.1). The UI changes nothing: no
card, no message, no toast. After a reload `/keys.list` still renders no
`[data-kind="keys"]` card, so there is no state for a removal to survive in.

## Selectors and routes

- Route: `DELETE /api/user/byok-keys/{provider}`.
- Card: `[data-kind="keys"]`; per-row button `[data-flow="keys.remove"]` (never rendered).
