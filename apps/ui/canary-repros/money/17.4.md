# 17.4 — checkout is exposed to MVP users

Origin: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
Account: `codeplanesmithers` (allowlisted, `admin:false`)
Tested: 2026-08-19

## Checklist row

> **17.4** No top-up or checkout flow is exposed to MVP users. `[auto D-3]`
> Note that `/billing.upgrade` and `/billing.portal` are registered flows —
> confirm they are unreachable for MVP accounts, or that reaching them is
> intended.

## Steps

1. Sign in on <https://canary.smithers.sh> as `codeplanesmithers`.
2. Type `/billing` in the composer and read the slash menu.
3. Send `/billing.upgrade`. Watch the network panel.

## Expected

Checkout is not reachable for an MVP account: neither flow is offered in the
slash menu, and running one is refused before it reaches Stripe.

## Actual

Both flows are registered AND advertised in the MVP slash menu, in Stripe's own
words:

```
/billing.upgrade   Upgrade your plan (opens Stripe checkout)
/billing.portal    Manage billing (opens the Stripe portal)
```

Running `/billing.upgrade` fires a live `POST /api/billing/checkout`, which
answers `400 {"message":"stripe billing is not configured"}`. The transcript
does not change at all — the seam's error string is dropped (see 19.3), so the
user sees a menu entry that promises checkout and then nothing happens.

`/billing.portal` behaves the same way against `POST /api/billing/portal`.

## Selectors and routes

- Registry: `[data-flows]` on the app shell contains `billing.upgrade` and `billing.portal`.
- Slash menu: `[role="option"]` / `[cmdk-item]` after typing `/billing`.
- Routes: `POST /api/billing/checkout`, `POST /api/billing/portal`.
- Source: `apps/ui/src/mainview/state/seams/BillingSeam.ts`.
