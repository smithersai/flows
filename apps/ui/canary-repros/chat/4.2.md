# 4.2 — markdown tables render as raw pipe text

- **Origin:** https://canary.smithers.sh
- **Bundle:** `/assets/index-BHHXuMoZ.js` (carries `data-flow`, post `command`→`flow` rename)
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selector:** `.sui-md` (the message markdown block), `table` / `td` / `th`
- **Screenshot:** `/tmp/canary-chat-4.2.png`

## Steps

1. Sign in at https://canary.smithers.sh.
2. Send one message whose body is a GitHub-flavored markdown table:

   ```
   Output exactly this markdown and nothing else:
   # H1 Title
   ## H2 Title

   | Col A | Col B |
   |---|---|
   | 1 | 2 |
   ```

   Use the textarea's value (paste or `fill`) — typing a newline submits.
3. Read the `.sui-md` block's `innerHTML`.

## Expected

Row 4.2 requires tables to render. The three source lines become a `<table>`
with a header row and one body row.

## Actual

`.sui-md` emits one paragraph holding the literal pipes:

```html
<p class="sui-md-p">Output exactly this markdown and nothing else:</p>
<div class="sui-md-heading sui-md-h1">H1 Title</div>
<div class="sui-md-heading sui-md-h2">H2 Title</div>
<p class="sui-md-p">| Col A | Col B |<br>|---|---|<br>| 1 | 2 |</p>
```

`document.querySelectorAll("table").length === 0` and
`document.querySelectorAll("td,th").length === 0`.

The rest of row 4.2 passes and is not part of this finding: headings render
(`.sui-md-heading.sui-md-h1` / `.sui-md-h2` — styled `div`s, not semantic
`h1`/`h2`), lists render as `ul`/`li`, links render as `a[href]`, inline code
renders as `code`, a fenced block with a language renders as `pre` with a
language label plus Wrap and Copy, and a 220-character unbroken token wraps
without horizontal page scroll (`documentElement.scrollWidth === clientWidth`).

Both the user bubble and the assistant bubble use the same renderer, so the
failure does not depend on what the model returns.
