# 4.6 — `/retry` duplicates the user message

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selectors:** `[data-role="user"]`, `[data-role="assistant"]`
- **Screenshot:** `/tmp/canary-chat-4.6.png`
- **Flow:** `retry` ("Retry the last turn")

## Steps

1. Sign in at https://canary.smithers.sh and clear the transcript.
2. Send `Reply with one random uncommon English noun, nothing else.`
3. Wait for the answer.
4. Send `/retry`.
5. Count the `[data-role="user"]` bubbles carrying that prompt.

## Expected

Row 4.6: "`/retry` re-runs the last turn and does not duplicate the user
message." One user bubble, its answer replaced (or a second answer under the
same prompt).

## Actual

The prompt is posted again. The transcript grows a user/assistant pair per
retry:

```
assistant: You have 6 open issues and 1 open pull request across 3 repos…
user:      Reply with one random uncommon English noun, nothing else.
assistant: Reasoning complete › Reasoning  quandary
user:      Reply with one random uncommon English noun, nothing else.   <-- re-posted
assistant: Reasoning complete › Reasoning  gloaming
```

`[data-role="user"]` count for the prompt goes 1 → 2. A third `/retry` makes it
3 (observed separately: 3 → 4 on a longer transcript). `/retry` itself is
correctly not echoed as a user message.

Because each retry re-sends the whole transcript, this also feeds the growth
that eventually wedges the turn seam — see [4.13](./4.13.md).
