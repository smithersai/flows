# 5.2 — the `typing → chat.stop` ordering never reaches a surface

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers` (plus a signed-out profile for the auth clause)
- **Selectors:** `.slash-menu [role=option]`, `.slash-menu-name`, `[data-gold]`, `button[aria-label="Stop generating"]`
- **Screenshot:** `/tmp/canary-chat-5.2.png`

## Steps

1. Sign in at https://canary.smithers.sh with a recommendation waiting.
2. Type `/` on the chat surface and read the leading item.
3. Run `/world`, type `/`, read the leading item.
4. Back on chat, start a long turn. Wait for the composer's ■ "Stop generating"
   button — the honest "a turn is streaming" signal — then type `/` and read the
   menu.
5. Separately, on a signed-out profile, type `/` and read the leading item.

## Expected

Row 5.2: "The recommendation order changes with state: **typing → `chat.stop`**;
signed out → `auth.sign-in`; a waiting recommendation → `reco.accept` first; off
the chat surface → `chat` first."

## Actual

Three of the four hold:

| state | leading item | gold |
|---|---|---|
| signed out | `/auth.sign-in` | yes, and `aria-selected` |
| reco waiting, chat surface | `/reco.accept` | yes |
| off the chat surface (`/world`) | `/chat` | yes |
| **a turn is streaming** | **the menu is empty (0 items)** | — |

`recommendedNames` does return `["chat.stop"]` first while `state.typing`
(`src/mainview/flows/registry.ts`), but nothing renders it:

- `App.tsx` suppresses the whole listing for exactly that state —
  `const slashMatches = slashQuery === undefined || typing ? [] : controller.slashItems(slashQuery)`
  — so the menu is empty, measured 0 items with the ■ button confirmed on screen.
- The derived suggestion-pill row does not consult `recommendedNames`; it
  branches on signed-out / needs-selection / reco only.

So the branch is unreachable in the shipped UI. The stop act is still offered
mid-stream — the composer swaps its Send button (which goes `disabled`) for a ■
"Stop generating" button — but that button carries no `data-flow`
(see [6.1](./6.1.md)), and typing `/stop` while streaming does nothing, because
the composer refuses every submit for the duration of the turn. Escape and the ■
button are the two working stop paths (row 4.8 passes, 117ms).
