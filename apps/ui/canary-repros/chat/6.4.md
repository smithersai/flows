# 6.4 — `/flows` lists 65 names; `data-flows` on the app shell carries 88

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selectors:** `[data-flows]` on `.app-shell`; the `/flows` card body
- **Screenshot:** `/tmp/canary-chat-6.4.png`

## Steps

1. Sign in at https://canary.smithers.sh.
2. Read `document.querySelector("[data-flows]").getAttribute("data-flows")` —
   88 space-separated names.
3. Run `/flows` and read the rendered listing — 65 `/<name> — <summary>` rows.

## Expected

Row 6.4: "`/flows` lists everything the app can do, and the list matches
`data-flows` on the app shell."

## Actual

65 of 88. The 23 names `/flows` omits are:

```
admin.grant.cancel  admin.grant.confirm  admin.queue.approve  approval.approve
approval.deny       card.maximize        card.minimize        connector.add
connector.downgrade connector.remove     copy-message         flow.repo.choose
flow.run.retry      flow.run.stop        repos.watch.all      repos.watch.confirm
repos.watch.none    repos.watch.toggle   stop                 toast.dismiss
world.delete        world.new-note       world.select
```

Those are exactly the 22 hidden id-scoped actions plus the `stop` alias — the
set row 5.7 requires never be listed, and 5.7 passes on this build (they are
absent from the slash menu even when you type their whole name, and they still
run when typed: `/world.new-note` created an "Untitled 1" note).

So the two rows disagree about one list. `App.tsx` documents `data-flows` as
"the live registry manifest (visible AND hidden names)", while `/flows` is
described as "List everything Smithers can do" for a person. Reported as a fail
against the row as written; the fix is likely to re-word row 6.4 to compare
`/flows` against the *visible* registry rather than to start listing hidden
id-scoped actions.
