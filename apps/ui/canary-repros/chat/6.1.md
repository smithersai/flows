# 6.1 — eight visible affordances carry no `data-flow`, though each has a registered flow

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selector:** `button,[role=button],[role=menuitem],[role=option],a[href],input[type=checkbox],summary` filtered to those with no `closest("[data-flow]")`
- **Screenshot:** `/tmp/canary-chat-6.1.png`

## Steps

1. Sign in at https://canary.smithers.sh.
2. On each of the three surfaces (chat, `/world`, `/connect`), enumerate the
   visible interactive elements and keep the ones with no `data-flow` ancestor.

## Expected

Row 6.1: "Every visible interactive affordance resolves to a named flow that is
also reachable by `/name`."

## Actual

Eight distinct affordances have no `data-flow` binding, and every one of them
names a flow that IS in the registry's `data-flows` manifest:

| affordance (`aria-label` or text) | the flow it should carry |
|-----------------------------------|--------------------------|
| `Show your balance` ($505 chip)   | `billing.balance`        |
| `Reset conversation`              | `reset`                  |
| `Toggle light and dark mode`      | `dark-mode`              |
| `Send message` (↑)                | `send`                   |
| `New note` (World)                | `world.new-note`         |
| `World` (file-tree entry)         | `world.select`           |
| `Delete World`                    | `world.delete`           |
| `The read behind this` (`SUMMARY`) | — a disclosure, arguably not a flow |

A ninth appears only mid-stream and is not in the run above: the composer's
`Stop generating` (■) button, which should carry `chat.stop`. The Send button is
`disabled` while a turn streams, which is how row 4.11 passes.
