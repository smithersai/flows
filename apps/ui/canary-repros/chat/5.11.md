# 5.11 — a malformed argument is refused silently; only a missing one says anything

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selector:** any leaf element matching `/didn.t run|needs a|needs an|expected|invalid|not a /i`; the refusals that do appear render as `/<name> didn't run` + the reason
- **Screenshot:** `/tmp/canary-chat-5.11.png`

## Steps

1. Sign in at https://canary.smithers.sh.
2. Clear the persisted transcript before each invocation (the refusal cards
   accumulate and a stale one reads as a fresh pass).
3. Submit each of the checklist's examples from the composer and watch for any
   rendered refusal for ~3.5s.

## Expected

Row 5.11: "Malformed arguments produce a readable error naming what was
expected, not a schema dump. Try `/issues.view abc`, `/admin.grant xyz will`,
`/env.set NOEQUALS`."

## Actual

Nothing is rendered for any malformed argument. The draft clears and the app is
silent — no toast, no card, no message. The control proves the surface works:
the *missing*-argument case shows the honest refusal.

| invocation              | rendered                                                   |
|-------------------------|------------------------------------------------------------|
| `/issues.view`          | `/issues.view didn't run` + `issues.view needs an issue number` |
| `/issues.view abc`      | — nothing —                                                 |
| `/issues.close abc`     | — nothing —                                                 |
| `/prs.view abc`         | — nothing —                                                 |
| `/admin.grant xyz will` | — nothing —                                                 |
| `/env.set NOEQUALS`     | — nothing —                                                 |

`SlashPayload.ts` has the right strings for these cases —
`numbered(args, "issues.view needs an issue number")` rejects `abc` because
`Number("abc")` is `NaN`, and `admin.grant` rejects a non-numeric amount with
`"admin.grant needs an amount in dollars and a login: /admin.grant 25 octocat"`.
They never reach the screen, so the parse result is being dropped somewhere
between `payloadFor` and the renderer on the with-arguments path only.

Two further notes on the same row:

- `/env.set NOEQUALS` is not even rejected: the parser only checks that the rest
  is non-empty, so `{ assignment: "NOEQUALS" }` is accepted and handed to the
  flow with no `=` in it.
- `/browser notaurl` **does** report honestly ("That is not a URL I can read."),
  because that refusal comes from the handler rather than the argument parser.
