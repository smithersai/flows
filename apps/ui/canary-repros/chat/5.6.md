# 5.6 — the 8-item cap is not applied to a bare `/` (65 items) or to prefix-heavy queries

- **Origin:** https://canary.smithers.sh
- **Tested:** 2026-08-18, signed in as `codeplanesmithers`
- **Selectors:** `.slash-menu [role=option]`, `.slash-menu-name`
- **Downstream failure:** [5.1](./5.1.md) — the uncapped 65-item listing is what overflows the viewport

## Steps

1. Sign in at https://canary.smithers.sh.
2. Park the pointer away from the composer (`page.mouse.move(1350, 20)`), clear
   the draft, and type each query below.
3. Count `.slash-menu [role=option]`.

## Expected

Row 5.6: "With more than 8 matches, the listing caps at 8 and ranks the
remainder by your recent commands."

## Actual

The cap holds for summary-match queries and leaks for everything else:

| query   | items |
|---------|-------|
| `/`     | 65    |
| `/a`    | 13    |
| `/re`   | 10    |
| `/i`    | 9     |
| `/s`    | 8     |
| `/list` | 8     |
| `/th`   | 8     |

`slashItems` (`src/mainview/flows/registry.ts`) never cuts an item whose
`nameRank <= 1`, and `nameRank` returns 0 when the query is empty:

```ts
const nameRank = (command, query) => { if (query === "") return 0; … }
const kept = (item) => item.recommended || nameRank(item.flow, query) <= 1;
const room = Math.max(SLASH_MENU_CAP, survivors.length) - survivors.length;   // 0 for a bare "/"
```

So on a bare `/` every one of the 65 visible flows counts as "named outright",
`survivors.length === 65`, `room === 0`, and the cap is a no-op — in exactly the
case its own doc comment describes as "a wall, not a menu". `/a`, `/re` and `/i`
leak the same way through genuine prefix matches.

The **recency half of the row passes**. Running `/debug.snapshot` and
`/debug.events` moves both into the capped `/s` listing, displacing `/browser`
and `/flow.list`.
