# 23.4 — two tabs diverge; there is no cross-tab sync

**Lane** honesty (§23) · **Origin** https://canary.smithers.sh ·
**Bundle** `assets/index-BHHXuMoZ.js` · **Observed** 2026-08-19, account
`codeplanesmithers`.

**Row** 23.4 — "Two tabs on the same session: state stays consistent; no
duplicated cards or divergent transcripts."

## Steps

1. Sign in on https://canary.smithers.sh.
2. Open a second tab on the same origin in the same browser profile. Let it
   settle (both tabs show the same transcript).
3. In tab A, send `Say exactly: <MARKER> and nothing else.`
4. Watch tab B for 45s without touching it.
5. Reload tab B.

## Expected

Both tabs show the same conversation. The turn sent in A appears in B.

## Actual

Tab A streams and completes the turn. Tab B never sees it — not at 10s, 20s,
30s or 40s. The two tabs show different transcripts for as long as B is left
alone. An explicit reload of B reconciles it.

```
t≈10s  tabA=true  tabB=false
t≈20s  tabA=true  tabB=false
t≈30s  tabA=true  tabB=false
t≈40s  tabA=true  tabB=false
tab B after an explicit reload: true
```

Mitigating: nothing is **duplicated** and nothing is **fabricated**. A separate
run counted card kinds in both tabs after reconciling — `Connectors` ×1 and
`Balance` ×1 in each, and the transcripts matched. The defect is staleness, not
corruption. But per the row's own wording, the transcripts do diverge.

The persistence is per-tab OPFS wa-sqlite (`/smithers-mvp.sqlite`, one file per
origin) with no BroadcastChannel/storage-event fan-out, so the second tab's
in-memory collections never learn about the first tab's writes.

## Route / selector

- composer `textarea.sui-chat-composer-input`
- persistence: OPFS `smithers-mvp.sqlite` (`@tanstack/browser-db-sqlite-persistence`)
