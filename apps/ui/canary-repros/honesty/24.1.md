# 24.1 — client error reporting is closed; silent swallowing is not

**Lane** honesty (§24) · **Origin** https://canary.smithers.sh ·
**Bundle** `assets/index-BHHXuMoZ.js` · **Observed** 2026-08-19.

**Row** 24.1 `[gap]` — "Client errors are only `console.error`. Decide whether
the alpha ships without client error reporting; if it does, confirm no
user-visible surface swallows an error silently."

## The first half is closed, and verified live

Appendix C item 6 is correct. `apps/ui/src/mainview/main.tsx` posts crashes and
unhandled rejections to `/api/client-errors`, the canary Worker accepts them,
and the reports are kept in the `CLIENT_ERRORS` Durable Object
(`apps/server/src/clientErrorLog.ts`), readable at `GET /api/admin/errors`.

Driven on the live canary:

```
client-error reports posted: 2
  {"kind":"unhandledrejection","message":"Error: HONESTY-24.1-unhandled-rejection …","url":"/","at":"2026-08-19T09:32:…"}
  {"kind":"error","message":"Error: HONESTY-24.1-window-error …","url":"/","at":"2026-08-19T09:32:36.863Z"}
```

and by hand: `POST /api/client-errors` → `202 {"status":"accepted"}`.
(`GET /api/admin/errors` answers the canonical 404 for a non-admin session, so
the read-back was not exercised — see row 24.7.)

## The second half is not met

Several user-visible surfaces swallow a failure in complete silence — no
message, no card, no toast, **and no `console.error`**, so they never reach the
client-error log either. The cleanest one is what the repro drives:

### Steps

1. Sign in on https://canary.smithers.sh.
2. Type the exact next step the app's own branches card prints:
   `/prs.create honesty 24.1 silent-swallow check from:codeplanesmithers-patch-1 codeplanesmithers/canary-sandbox`

### Expected

A pull request, or an honest named failure — the shape `/issues.list` uses:
"`/issues.list` didn't run — Several repositories are watched … name one as
owner/repo".

### Actual

```
composer cleared (the submit fired): true
backend reads it made: ["GET /api/repos/codeplanesmithers/canary-sandbox/bookmarks?limit=100","GET /api/repos/codeplanesmithers/canary-sandbox/changes?limit=100"]
lines it added to the UI: []
console errors: []
client-error reports for it: 0
```

The other silent surfaces found in this lane:

- **billing** — with its upstream unreachable, `/billing.balance` renders no
  message at all; it re-stamps the Balance card instead (row 24.2).
- **workflow provision** — `/flow.create` + a repository choice leaves
  "Preparing your `<repo>` workspace…" standing past 120s with no timeout, no
  error and no card, because `POST /api/workflow/provision` never answers
  (row 22.6).

So the alpha does now have client error reporting, but the errors that matter
most here never become errors: they are dropped before anything logs them.

## Route / selector

- reporting: `POST /api/client-errors`, read-back `GET /api/admin/errors`
- swallow: composer `textarea.sui-chat-composer-input` → `prs.create`;
  `GET /api/repos/{owner}/{repo}/bookmarks`, `…/changes`
