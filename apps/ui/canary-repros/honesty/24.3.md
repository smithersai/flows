# 24.3 — a provider 429 is pasted into the chat as raw JSON

**Lane** honesty (§24) · **Origin** https://canary.smithers.sh ·
**Bundle** `assets/index-BHHXuMoZ.js` · **Observed** 2026-08-19.

**Row** 24.3 — "A 429 from the model provider surfaces as a rate-limit message,
not a generic failure."

## Steps

1. Sign in on https://canary.smithers.sh.
2. Intercept `**/api/agent/turn**` and answer HTTP 429 with a provider-shaped
   body:
   `{"type":"error","error":{"type":"rate_limit_error","message":"Number of request tokens has exceeded your per-minute rate limit"}}`
3. Send any prompt.

## Expected

A rate-limit message — that the model provider is rate-limiting, and when to
try again.

## Actual

The upstream's raw JSON body is concatenated onto a fixed prefix and shown to
the user:

```
I couldn't complete that turn. Smithers web agent failed (HTTP 429): {"type":"error","error":{"type":"rate_limit_error","message":"Number of request tokens has exceeded your per-minute rate limit"}}
Turn failed
```

There is no 429 branch anywhere in `apps/ui/src/mainview`
(`grep -rn "429" src/mainview --include=*.ts --include=*.tsx` excluding the
`#24292e` color token returns **0** hits). The turn seam's error path renders
`HTTP <status>: <body>` for every status.

## What this row does get right

A 429 raised by our **own** limiter reads correctly, because
`apps/server/src/turnLimit.ts` puts prose in the `message` field and that prose
survives the concatenation:

```
I couldn't complete that turn. Smithers web agent failed (HTTP 429): That is more
than 120 turns in an hour, which no one types by hand — something is looping. Chat
resumes on its own in about 12 minutes. Nothing was charged and your balance is
untouched.
```

So the fix is narrow: classify the status in the UI rather than relying on every
upstream to write user-facing prose. It also matters for row 24.4 — a Worker 500
whose body is a Cloudflare HTML page renders as
`… failed (HTTP 500): <!DOCTYPE html><html><body>Error 1101 Worker threw exception</body></html>`
in the transcript.

## Route / selector

- `POST /api/agent/turn`
- composer `textarea.sui-chat-composer-input`
- the message renders in the transcript with a `Turn failed` badge and a
  `Try again` affordance
