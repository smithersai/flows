# 24.2 — billing fabricates a fresh balance when its upstream is down; identity names the wrong cause

**Lane** honesty (§24) · **Origin** https://canary.smithers.sh ·
**Bundle** `assets/index-BHHXuMoZ.js` · **Observed** 2026-08-19, account
`codeplanesmithers`.

**Row** 24.2 — "Every upstream the UI calls, forced to fail: agent turn,
identity, billing, reco, notifications, github import, workflow rpc. Each
produces a named, actionable message."

Each upstream was made unreachable with Playwright route interception
(`route.abort("failed")` — the honest simulation of "the upstream is down"),
then the flow that calls it was invoked.

## A. billing — a fabricated success

### Steps

1. Sign in and let the balance card render once from a real read.
2. Note the card's stamp and value (`balance · 02:27 AM`, `$538 left.`).
3. Intercept `**/api/billing/**` and abort every request.
4. Type `/billing.balance`.

### Expected

"I couldn't read your balance — the billing service didn't answer", or the card
marked stale. Anything that does not assert a number the app could not fetch.

### Actual

The Balance card **re-stamps itself with the current time** and keeps asserting
the old figure as if it had just been read:

```
A. billing  hits=1  card "balance · 02:27 AM" $538 left. → "balance · 02:28 AM" $538 left.  honest-message=false
```

No message anywhere in the transcript names billing. The only trace of the
failure is `console.error: Failed to load resource: net::ERR_FAILED`.

The same shape with a 500 instead of an abort: two failed `GET /api/billing/balance`
calls, and the user sees a `balance · <now>` card reading `$505 left.` /
`$0 spent across 1649 turns so far.`

This is the row's worst case and the lane's headline finding: it is not a
missing error message, it is the UI stating a fact it could not verify. It also
plants the number the model then contradicts in row 22.7.

## B. identity — the named cause cannot be true

### Steps

1. Intercept `**/api/auth/session**` and abort. Load the app.

### Actual

```
$538
This build isn't connected to Smithers' identity service, so GitHub sign-in and
repository features are off here. Everything local still works — the World, the
browser, local repositories, and workflows on connected work. Use the deployed
app for the signed-in experience.
```

Two problems. The cause is wrong — this is a transient upstream failure, not a
build without `IDENTITY_UPSTREAM_URL`; the canary sets that var
(`apps/server/wrangler.jsonc`). And the next step is unactionable: the user is
already on the deployed app. Meanwhile the header still renders `$538` as if the
session were live.
