# 10.2 — `world.new-note` creates a note and focuses it

- **Origin:** https://canary.smithers.sh (Worker `smithers-mvp-web`, deployment `4cd23e9a-14a0-4947-8d45-2bc7c59e0db0`)
- **Account:** `codeplanesmithers`
- **Verdict:** FAIL — the note is created and selected; focus is not moved into it.

## Steps

1. Sign in on https://canary.smithers.sh.
2. Run `/world` to open the World pane.
3. Click **New note** in the pane header.
4. Without clicking anywhere, type.

## Expected

The note is created, selected, and focused — typing immediately after creating
a note goes into the new note.

## Actual

The note is created (`Untitled 3` joins the sidebar tree) and selected
(`.world-document-meta` reads `Untitled 3.md`, the editor's `aria-label`
becomes `Edit Untitled 3`), but `document.activeElement` is still the **New
note** button:

```
document.activeElement after world.new-note:
  {"tag":"BUTTON","className":"sui-button sui-button-ghost sui-button-sm","insideEditor":false}
```

Typing 22 characters straight after creation leaves the note's body unchanged
(it still reads only its title placeholder), so the keystrokes are swallowed by
the button, not written into the note.

## Root cause

`apps/ui/src/mainview/App.tsx` renders the header action as a plain
`<Button onClick={() => controller.runCommand("world.new-note")}>` and the
`world.new-note` handler selects the new document but never focuses the
`MarkdownEditor`. `MarkdownEditor` (`@smthrs/ui/adapters/markdown-editor`)
exposes an imperative handle but no autofocus, and the World pane does not hold
a ref to it.

Related, not graded here: that same **New note** button carries no `data-flow`
attribute, unlike every other visible affordance.

## Selectors / routes

- Pane: `section.world-surface`
- Trigger: `section.world-surface .surface-header button:has-text('New note')`
- Editor that should take focus: `.world-document .ProseMirror`
  (inside `.sui-markdown-editor[aria-label="Edit <title>"]`)
