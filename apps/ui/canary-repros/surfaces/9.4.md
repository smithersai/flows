## Root cause

The recommendation is computed by the reco Worker from the **GitHub** API
(`workers/recommendations/src/github.ts`), but the pull-request flows the
accepted proposal routes into read the **Smithers Cloud landing index**
(`GET /api/repos/:owner/:repo/landings`). The two sides do not describe the
same thing, so every "review pull request N" recommendation is unactionable:
`prs.view 2` 404s with "landing request not found", and `prs.list` never names
the pull request the recommendation is about.

Confirmed twice, from both sides of the mismatch. At 05:36Z the landing index
was empty and the card read "No pull requests in
codeplanesmithers/canary-sandbox" while GitHub had #2 open. At 06:22Z a sibling
lane had created a landing, and the same card read:

```
Pull requests · codeplanesmithers/canary-sandbox      DONE
#1 Canary cards fixture landing   by codeplanesmithers   OPEN
```

— one landing request that is not a GitHub pull request, presented as a pull
request, and still no #2. The card is not a view of GitHub at all.

card alone, asserts positively that every open GitHub pull request is named
there, and exits **2** rather than 1 when the session is turn-rate-limited or
no card rendered.
