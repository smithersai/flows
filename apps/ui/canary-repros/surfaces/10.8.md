# 10.8 — The world content actually reaches the model

- **Origin:** https://canary.smithers.sh (Worker `smithers-mvp-web`, deployment `4cd23e9a-14a0-4947-8d45-2bc7c59e0db0`)
- **Account:** `codeplanesmithers`
- **Verdict:** FAIL — a World note's body never reaches the model.

## Steps

1. Sign in on https://canary.smithers.sh.
2. Run `/world`, select a note, and replace its body with a fact recorded
   nowhere else:
   `Project glossary. The canary codeword for this workspace is zarquon-mimsy-7741. Nothing else records it.`
3. Wait for the edit to settle (it persists — row 10.5 passes).
4. Run `/chat` and ask: *"What is the canary codeword for this workspace?
   Answer with only the codeword."*

## Expected

The model answers `zarquon-mimsy-7741`, because that is what the World note
says and the World pane's own subtitle is "What Smithers currently
understands".

## Actual

```
Reasoning
I can’t retrieve that codeword. The only way to get it would be to read a
specific file from a repository, but I don’t know which one to look at. If you
tell me the repository and path where the codeword is stored, I can read it for
you.
```

The model does not know the note exists as content. It is not a refusal or a
hallucination — the value genuinely is not in its context.

## Root cause

The runtime context the client sends with every turn carries world documents by
**metadata only**. `apps/ui/src/mainview/state/AppController.ts` maps each
document to `{ path, title, confidence }`, and
`apps/shared/src/AgentContext.ts` renders that as:

```
- World state: 2 document(s):
  - World.md — "World" (confidence 1)
```

The `body` field is never included, and no tool in the toolkit reads a world
note, so there is no path — eager or lazy — by which note content reaches the
model.

## Selectors / routes

- Pane: `section.world-surface`
- Editor: `.world-document .ProseMirror` (Milkdown Crepe, `role="textbox"`)
- Turn: `POST /api/agent/turn`
- Context shape: `AgentRuntimeContextSchema.worldState.documents` in
  `apps/shared/src/AgentContext.ts`

Two runs, two shapes of the same failure. In the first the model said it could
not retrieve the value and asked for a repository and path; in the second it
guessed "Canary." and then reached for `/files.read` against the watched
repositories. Neither run looked at the World note, because there is nothing in
the context or the toolkit that would let it.

The repro clears the origin's persisted store first (cookies survive) so the
answer check reads this run's transcript, and exits **2**, not 1, when the
session is turn-rate-limited (the product Worker caps a session at 120 turns an
hour and renders that cap with the closed-alpha copy, "Smithers is open to
design partners only right now", which would otherwise be misread as this bug).
