# 26.1 — the chain backend cannot run a turn on the canary

Origin: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
Account: `codeplanesmithers` (`admin:true` via the ADMIN_LOGINS fixture)
Tested: 2026-08-19, admin lane round 1

## Checklist row

> **26.1** `/debug.backend proxy` and `/debug.backend chain` both switch the
> agent backend and a turn works on each.

## Steps

1. Sign in as an admin (the `debug.*` flows only register for `admin:true`).
2. `/debug.backend chain`, then send `Reply with exactly: PONG-chain`.
3. `/debug.backend proxy`, then send `Reply with exactly: PONG-proxy`.

## Expected

Both backends answer the turn.

## Actual

- **proxy** — the turn completes and the reply lands. ✅
- **chain** — three `501 POST /api/model/stream` responses, then the transcript
  shows:

  > I couldn't complete that turn. The chain failed:
  > `Cause([Fail(/chain/AuthorError: flows/model/ModelError: provider_internal:`
  > `Anthropic Messages request failed with HTTP 501 (cause: "provider_internal"))])`
  > **Turn failed**

  The failure is honest, but the turn never runs.

Neither `/debug.backend proxy` nor `/debug.backend chain` renders any
confirmation that the backend switched — see `26.2.md` for that defect.

## Root cause

The chain backend drives the browser model relay at `POST /api/model/stream`.
`apps/server/src/ModelStream.test.ts` states the contract: "an unconfigured
relay answers 501 instead of forwarding a request that can only come back 401".
The deployed product Worker has no relay key:

```
$ curl .../workers/scripts/smithers-mvp-web/settings   # bindings, names only
ASSETS, BILLING_ADMIN_TOKEN, BILLING_AUTH_TOKEN, BILLING_PRODUCT_SERVICE_TOKEN,
BILLING_UPSTREAM_URL, CHAT_PRODUCT_SERVICE_TOKEN, CLIENT_ERRORS,
GATEWAY_SESSIONS, IDENTITY_ADMIN_TOKEN, IDENTITY_SERVICE_TOKEN,
IDENTITY_UPSTREAM_URL, RECO_ADMIN_TOKEN, RECO_UPSTREAM_URL,
SMITHERS_CHAT_AUTH_TOKEN, SMITHERS_CHAT_ORIGIN, SMITHERS_CHAT_URL,
SMITHERS_CLOUD_API_BASE_URL, TURN_CANCELS, TURN_LIMITS
```

`MODEL_RELAY_API_KEY` is absent. The proxy backend works because it goes to
`smithers-cloud-chat-canary` (Cerebras, metered through billing) instead.

**Not fixed as a fixture on purpose.** Binding a raw provider key on the
product Worker opens an unmetered relay to every signed-in user, which is a
cost and security decision for the owner, not a test fixture. Either bind the
key deliberately, or drop `chain` from `debug.backend`'s accepted values on
deployments without a relay so the flow refuses honestly instead of producing
a failed turn.
