# §21.4 — Escape skips "close menu" whenever focus is outside the menu

**Row:** `21.4` — "Escape has one meaning per context and the precedence is
right: stop turn while typing → minimize maximized card → dismiss
recommendation → close menu."

**Verdict:** FAIL on the last step of the chain.

**Target:** https://canary.smithers.sh
**Route:** `/` (chat surface)
**Selectors:** `[data-flow="surfaces"]` (the menu trigger), `[role="menu"]`,
`[data-flow="copy-message"]`, `section[data-kind="reco"]`,
`[data-flow="card.maximize"]` / `[data-flow="card.minimize"]`
**Repro:** `bun canary-repros/appearance/21.4.ts` (exits 1 while the bug is present)

## What works

| context | Escape does | verdict |
| --- | --- | --- |
| a turn is streaming, focus in the composer | stops the turn ("Stopped the current response." / "Turn interrupted"); the recommendation is left alone | correct |
| a card is maximized, a recommendation is waiting | minimizes the card, returns focus to the maximize button, leaves the recommendation | correct |
| a recommendation is waiting, nothing else open | dismisses the recommendation | correct |
| a menu is open **and focus is inside it** | closes the menu, returns focus to the trigger | correct |

## What fails

| context | expected | actual |
| --- | --- | --- |
| a menu is open and focus is anywhere else in the app shell | close the menu | the menu stays open **and the recommendation is dismissed instead** |
| Tab from inside an open menu | stay in, or close the menu | focus lands on `<body>`, outside the app shell, with the menu still open; Escape there does nothing at all |

## Steps

1. Open https://canary.smithers.sh signed in, with a recommendation card in the
   transcript (`section[data-kind="reco"]`).
2. Focus `[data-flow="surfaces"]` and press Enter. `[role="menu"]` appears.
3. Move focus to any other control — Tab, or focus `[data-flow="copy-message"]`.
   The menu is still open.
4. Press Escape.

## Expected

The open menu closes. The recommendation is untouched.

## Actual

The menu count stays at 1 and the recommendation count goes 1 → 0. The user
loses the recommendation — and it is suppressed for 7 days — for pressing
Escape at an open menu.

Cause, visible in `apps/ui/src/mainview/App.tsx`: the menu's Escape lives in the
menu's own `onKeyDown` (`onMenuKeyDown`), while the shell's `onKeyDown` on
`.app-shell` handles only maximized-card → recommendation → Cmd/Ctrl+Shift+D.
Nothing in the shell asks "is a menu open?" before reaching the recommendation
branch, so "close menu" is not actually last in a precedence chain — it is a
separate handler that only fires when the menu holds focus.

## Restoring the fixture

Running this repro dismisses a recommendation for the signed-in login. Undo it
with the admin door, from an admin session on the app origin:

```
DELETE /api/admin/reco-dismissals?login=<login>   ->  {"login":"…","cleared":N}
```
