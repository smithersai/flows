# §21.2 — forward Tab is trapped in the world editor (and mutates the note)

**Row:** `21.2` — "Tab order is sane on every surface; no focus trap; no
unreachable control."

**Verdict:** FAIL.

**Target:** https://canary.smithers.sh
**Route:** `/world` (the world editor)
**Selector:** `.ProseMirror` (`role="textbox"`, the Milkdown/ProseMirror body)
**Repro:** `bun canary-repros/appearance/21.2.ts` (exits 1 while the bug is
present; restores the note text before it exits)

## What passes

| surface | tab stops before `<body>` | visible focusables | never reached by Tab | Shift+Tab returns to `<body>` |
| --- | --- | --- | --- | --- |
| chat | 18 | 18 | none | yes |
| connectors | 21 | 20 | none | yes |

Order follows the document on both: corner chrome → transcript region → the
controls of each message and card in order → composer → composer chrome →
surface chrome. Every stop except the composer textarea paints a visible ring.

## What fails

### 1. The world editor traps forward Tab

Focus `.ProseMirror` and press Tab. Focus does not move — five presses in a row
leave `document.activeElement` on `.ProseMirror` — because the editor binds Tab
to "insert indentation". Every press also **writes whitespace into the note**.
The only escape is Shift+Tab (which lands on "Delete World"). A keyboard user
tabbing through the world surface reaches the editor and cannot get past it.

Observed over 6 presses in an exploratory run, the note went
`World` → `W    orld` → `W        orld` → … → `W                        orld`.
(That damage was repaired: the note is back to `World`.)

The `.ProseMirror` element also has no accessible name — see §20.6, axe rule
`aria-input-field-name`.

### 2. A static status pill is in the tab order

On the connectors surface, stop 19 is
`SPAN[tabindex="0"] "CONNECTED ✓ AS CODEPLANESMITHERS"` — a non-interactive
badge. It takes a tab stop and does nothing when activated.

### 3. Tab from inside an open menu leaves the document with the menu open

Open `[data-flow="surfaces"]` with Enter, then press Tab: focus lands on
`<body>`, outside `.app-shell`, while `[role="menu"]` is still mounted. Escape
there does nothing at all (the shell's key handler never sees it). See §21.4.

### 4. Focus is dropped to `<body>` after a card action

Activating `[data-flow="reco.edit"]` ("Edit first") with Enter leaves
`document.activeElement === document.body`. A keyboard user loses their place
and has to Tab from the top of the page.

## Note for the fix stage

Milkdown/ProseMirror ships a Tab keymap. The usual fix is to drop the Tab
binding (leave indentation to the list commands) or to make Tab move focus and
require a modifier to indent, plus give `.ProseMirror` an `aria-label`.
