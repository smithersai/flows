# 15.2 — `/files.list` on a path that does not exist says nothing at all

- Lane: `repo-data` (checklist §15)
- Target: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
- Account: `codeplanesmithers` (signed in, allowlisted)
- Date: 2026-08-19

## Steps

1. Open <https://canary.smithers.sh> signed in as `codeplanesmithers`.
2. Type `/files.list does/not/exist codeplanesmithers/canary-sandbox` into the
   composer and press Enter.
3. Wait 20 s.

## Expected

An honest rendering of the miss: a card or a message saying the path is not in
the repository, ideally naming the next step (`/files.list` at the parent).

## Actual

Nothing renders. No `[data-kind]` card is added, no transcript text is
appended, no toast appears. The composer clears, so the turn was accepted and
then dropped on the floor. A user cannot tell a missing path from a broken app.

The platform itself is honest — the browser makes exactly one request and gets
a clean 404:

```
404 GET https://canary.smithers.sh/api/repos/codeplanesmithers/canary-sandbox/contents/does/not/exist
{"message":"content not found"}
```

## Route / selector

- Route: `GET /api/repos/{owner}/{repo}/contents/{path}` → 404
- Flow: `files.list` (`data-flow="files.list"`), submitted through the composer
- Code: `AppController.send` runs a slash flow with `commands.run(...)` and
  never calls `surfaceCommandFailure`, so the seam's refusal string
  (`FilesSeam`) is discarded. `runCommandArgs` (the button path) *does* toast
  it — only the typed path is silent.
