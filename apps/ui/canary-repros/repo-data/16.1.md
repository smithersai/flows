# 16.1 — `/flow.create` reports a finished run and creates no workflow

- Lane: `repo-data` (checklist §16)
- Target: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)

  `b5784a63-3186-4e9f-98b3-ee3c30be30bb`
- Date: 2026-08-19

## Steps

1. `/flow.list` — record the workspace's workflows.
2. `/flow.create write a HELLO-CANARY.md file greeting the repo owner codeplanesmithers/demo-calendar`
3. Wait for the `flow-run` card to finish.
4. `/flow.list` again.

## Expected

Per the checklist row: "`/flow.create <description>` produces a workflow, and
the created workflow is real on the workspace." The list gains an entry, and
the card names what was created.

## Actual

The launch half is real. `POST /api/workflow/rpc` starts a genuine
`create-workflow` run (`workflowPath /root/.smithers/workflows/create-workflow.tsx`)
and the card follows it live.

The result half is empty:

- the run ends in 690 ms with 2 steps (`clarify`, `output`),
- the card says "Finished." and renders no result body and no next step,
- `/flow.list` afterwards returns exactly the same eight workflows.

Reading the run's own events (`GET /api/workflow/events`) shows why: the
`clarify` node routes the request to `"tier": "direct"` with
`"reason": "The request is a simple file creation, which can be done directly
without a workflow."` and the `output` node emits an empty string. So the
builder decided not to build anything — and the UI reported that decision as a
finished creation with no words at all. The user asked for a workflow, was told
the run finished, and has neither a workflow nor a reason.

This is not a missing AI credential: the same events show the model reasoning
normally (it produced a full plan object with `name: "hello-canary"`, a goal,
stages and success criteria before choosing the `direct` tier).
