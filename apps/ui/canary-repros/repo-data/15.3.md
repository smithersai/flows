# 15.3 — `/files.read` is dishonest on a binary file and silent on a missing one

- Lane: `repo-data` (checklist §15)
- Target: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
- Account: `codeplanesmithers` (signed in, allowlisted)
- Fixture repo: `codeplanesmithers/canary-sandbox`
  (`README.md` 54 B, `big.txt` 162 KB, `blob.bin` 4 KiB of random bytes,
  `docs/nested/hello.txt` 66 B)
- Date: 2026-08-19

## Steps

Run each of these through the composer against
`codeplanesmithers/canary-sandbox`:

1. `/files.read docs/nested/hello.txt codeplanesmithers/canary-sandbox`
2. `/files.read README.md codeplanesmithers/canary-sandbox`
3. `/files.read big.txt codeplanesmithers/canary-sandbox`
4. `/files.read blob.bin codeplanesmithers/canary-sandbox`
5. `/files.read nope-missing.txt codeplanesmithers/canary-sandbox`

## Expected

Five readings, each honest about what it is.

## Actual

Three of the five are fine:

- plain text renders its contents,
- `README.md` renders its markdown source verbatim,
- `big.txt` renders a prefix and closes with
  "Truncated — the full file stays in the repository."

Two are not:

- **`blob.bin`** renders the raw base64 body of the blob as if it were the
  file's text. Nothing on the card says the file is binary, says how large it
  is, or offers a next step. The card reads exactly like a text file whose
  contents happen to be `lh028CNPxKiO9IS02FoeS1XRinEDY…`.
- **`nope-missing.txt`** renders nothing at all: no card, no message, no toast
  (same silent-refusal class as §15.2 and §15.7).

## Route / selector

- Route: `GET /api/repos/{owner}/{repo}/contents/{path}`; the missing file
  answers `404 {"message":"content not found"}`.
- Flow: `files.read` (`data-flow="files.read"`); card kind `file`
  (`[data-kind="file"]`).
- The binary half is a `FilesSeam` rendering gap — the GitHub contents API
  answers base64 and the seam treats it as text. The missing half is the
  `AppController.send` swallow described in `15.2.md`.
