# 15.7 — a malformed `/env.set` is refused silently

- Lane: `repo-data` (checklist §15)
- Target: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
- Account: `codeplanesmithers` (signed in, allowlisted)
- Date: 2026-08-19

## Steps

1. Open <https://canary.smithers.sh> signed in as `codeplanesmithers`.
2. Type `/env.set oops-no-equals codeplanesmithers/canary-sandbox` and press
   Enter.
3. Wait 20 s.

## Expected

The refusal the seam already writes — "env.set needs a NAME=value pair" — shown
in the transcript or as a toast, so the user learns the argument shape.

## Actual

Nothing at all: no card, no appended transcript text, no toast. The composer
clears and the turn disappears. Same silent-refusal class as §15.2 and the
missing-file half of §15.3.

## Route / selector

- Flow: `env.set` (`data-flow="env.set"`), submitted through the composer
- No network request is made — the refusal happens client side in
  `EnvironmentSeam.parseAssignment`.
- Code: the returned refusal string becomes a failed `CommandOutcome`, and
  `AppController.send` runs slash flows with bare `commands.run(...)`, which
  skips `surfaceCommandFailure`. The same flow invoked from a button
  (`runCommandArgs`) would toast `/env.set didn't run`.
