# 15.6 — `/env.set` stores the value as a plain variable, so it stays readable

- Lane: `repo-data` (checklist §15)
- Target: <https://canary.smithers.sh> (bundle `assets/index-BHHXuMoZ.js`)
- Account: `codeplanesmithers` (signed in, allowlisted)
- Date: 2026-08-19

## Steps

1. Open <https://canary.smithers.sh> signed in as `codeplanesmithers`.
2. `/env.set CANARY_ROW156_REPRO=fake-value-not-a-secret-19aug codeplanesmithers/canary-sandbox`
3. `/env.view codeplanesmithers/canary-sandbox`

## Expected

Per the checklist row: the set is confirmed **and the value never appears in
plain text afterwards**.

## Actual

The set half works — the PUT lands and the `env` card refreshes with the new
name. The masking half does not: the value is rendered in full on the
confirming card and on every later `/env.view`:

```
CANARY_ROW156_REPRO   fake-value-not-a-secret-19aug
```

`EnvironmentSeam.setEnvironmentVar` merges the pair into the platform's `env`
list (plain variables, values returned by the read) and never into the
`secrets` list (write-only, names only). There is no flow that writes a secret,
so nothing typed through `/env.set` can ever be masked.

Related, same code path: the read-merge-write PUT sends only
`{setup_script, env}` and drops the `secrets` array from the document it just
read, so every `/env.set` re-writes the environment without its secrets.

`/env.view` itself does mask real secrets and labels them
("SECRET — WRITE-ONLY"), so §15.5 is unaffected.
