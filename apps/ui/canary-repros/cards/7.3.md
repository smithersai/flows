# 7.3 — the card status pill is clipped at phone width

- **Origin:** https://canary.smithers.sh (bundle `/assets/index-BHHXuMoZ.js`)
- **Account:** `codeplanesmithers`
- **Repro:** `bun apps/ui/canary-repros/cards/7.3.ts`
- **Screenshot:** `/tmp/canary-cards-7.3-narrow.png`
- **Selector:** `[data-kind] .smithers-card-header .sui-badge`

## Steps

1. Open https://canary.smithers.sh signed in, viewport **390x844**.
2. Run `/billing.balance`, `/issues.list codeplanesmithers/canary-sandbox`,
   `/branches.list codeplanesmithers/canary-sandbox`,
   `/env.view codeplanesmithers/canary-sandbox`.
3. For each `[data-kind]` card compare its badge's `scrollWidth` to its
   `clientWidth`.

## Expected

The status pill is the most glanceable claim on a card, so it renders in full at
every width. If the header runs out of room, the *title* gives way — it is the
element that can be truncated without losing information the pill carries.

## Actual

The header is one non-wrapping row of title, pill, meta and the maximize button,
and the title never shrinks (`scrollWidth === clientWidth` on every title
measured). The pill absorbs the whole shortfall. At 390px:

| card | pill | needs | gets |
| --- | --- | --- | --- |
| `issue-list` | DONE | 64px | 20px |
| `pr-list` | DONE | 64px | 20px |
| `branches` | DONE | 64px | 20px |
| `repo-import` | FAILED | 71px | 23px |
| `file-list` | DONE | 64px | 20px |
| `env` | DONE | 64px | 38px |
| `file` | DONE | 64px | 32px |
| `pr` | DONE | 64px | 38px |
| `issue` | DONE | 64px | 27px |
| `theme-picker` | PENDING | 83px | 77px |
| `admin-health` | PENDING | 83px | 63px |
| `reco` | WAITING FOR APPROVAL | 171px | 138px |

A 20px box for a 64px `DONE` renders as a single clipped glyph. Cards whose
title carries a repo name (`Branches · codeplanesmithers/canary-sandbox`) are
the worst hit, which is most of the catalog.

At 1280px every pill measured renders in full, so this is a narrow-width
regression only.

The pill *values* are correct for every state reached in this pass — `waiting`,
`running`, `waiting-approval`, `done`, `failed` — and no card was observed
sitting on `running` after its work ended (a `create-skill` run went
`running` → `waiting-approval` → `done`; a failed import went straight to
`failed`).
