# 7.7 — a failed upstream call renders nothing at all

- **Origin:** https://canary.smithers.sh (bundle `/assets/index-BHHXuMoZ.js`)
- **Account:** `codeplanesmithers`
- **Repro:** `bun apps/ui/canary-repros/cards/7.7.ts`
- **Screenshot:** `/tmp/canary-cards-7.7-silent.png`
- **Routes:** `GET /api/repos/{owner}/{repo}/landings/{n}`,
  `GET /api/repos/{owner}/{repo}/contents/{path}`

## Steps

1. Open https://canary.smithers.sh signed in.
2. Run `/prs.view 99 codeplanesmithers/canary-sandbox` (landing 99 does not
   exist; the route answers HTTP 404).
3. Run `/files.read does-not-exist.txt codeplanesmithers/canary-sandbox` (the
   contents route answers HTTP 404).

## Expected

Each produces a card — or at minimum a transcript line — that says what failed
and offers the next step. `/repos.import codeplanesmithers/no-such-repo-canary-xyz`
is the model: a `repo-import` card with `data-status="error"`, a `FAILED` pill,
the upstream's own words (`github repository not found`) and a **Try again**
button.

## Actual

Nothing renders. No card, no transcript line, no toast. The only trace is a
`Failed to load resource: the server responded with a status of 404` in the
console. Both seams do build an error string —
`LandingsSeam.surfaceLanding`'s `readErrorMessage`
(`apps/ui/src/mainview/state/seams/LandingsSeam.ts:263`) and the equivalent in
`FilesSeam` — so the string is produced and then dropped on the floor.
