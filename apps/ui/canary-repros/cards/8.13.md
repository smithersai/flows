# 8.13 — the browser card renders a silent blank for every third-party site

- **Origin:** https://canary.smithers.sh (bundle `/assets/index-BHHXuMoZ.js`)
- **Account:** `codeplanesmithers`
- **Repro:** `bun apps/ui/canary-repros/cards/8.13.ts`
- **Screenshot:** `/tmp/cardslane/browser.png` (the blank frame and the blocked
  frame side by side)
- **Selector:** `[data-kind="browser"] iframe.browser-card-frame`

## Steps

1. Open https://canary.smithers.sh signed in.
2. Run `/browser https://example.com`.
3. Read `page.frames()`.

## Expected

The card frames the page, or — when the site refuses embedding — says so and
offers **Open in a new tab**. `BrowserCardBody`'s own comment states the
contract: "a next step, never a silent blank".

## Actual

The card renders its header, the URL line, and an **empty white box**. The
iframe has navigated to `chrome-error://chromewebdata/`. No message, no link,
and the pill still reads `DONE`.

## Root cause

The app origin answers with `cross-origin-embedder-policy: require-corp`:

```
$ curl -sI https://canary.smithers.sh/ | grep -i cross-origin
cross-origin-embedder-policy: require-corp
cross-origin-opener-policy: same-origin
```

Under COEP `require-corp` Chrome blocks every cross-origin frame whose response
carries no `cross-origin-resource-policy` header. `https://example.com` sends
none, so the frame is blocked before it loads and the card's `frameable`
pre-check (which asks the server, not the browser) never learns about it.

The repro proves the cause, not just the symptom: it runs the same flow twice,
once against the live headers and once with a route interceptor that strips only
`cross-origin-embedder-policy` from the app document. Stripped, the identical
iframe loads `https://example.com` and renders "Example Domain".

Practically every site on the public web omits CORP, so the `browser` card is
blank for all of them on this deployment.

The other two sub-cases in the row were reachable and behave:

- a site that refuses embedding (`https://canary.smithers.sh/...`) renders
  "The site refuses embedding (X-Frame-Options: SAMEORIGIN)." plus an
  **Open in a new tab** link;
- a genuine 404 and a very large page could not be distinguished from the blank
  case while COEP blocks the frame, so they are unverified.
