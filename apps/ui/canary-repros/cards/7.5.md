# 7.5 — a card created first renders below a later message

- **Origin:** https://canary.smithers.sh (bundle `/assets/index-BHHXuMoZ.js`)
- **Account:** `codeplanesmithers`
- **Repro:** `bun apps/ui/canary-repros/cards/7.5.ts`
- **Screenshot:** `/tmp/canary-cards-7.5-order.png`
- **Selector:** children of `.sui-chat-messages`

## Steps

1. Open https://canary.smithers.sh signed in and clear the persisted store
   (the repro does this over CDP, since the page holds sync access handles on
   the OPFS sqlite file).
2. Run `/billing.balance`. The transcript reads
   `[opening digest, reco card, balance card]`.
3. Send a plain chat message (`reply with the word ping`).
4. Read the transcript order again, then reload and read it a third time.

## Expected

The balance card was created before the chat message, so it keeps its place
above it — before and after a reload.

## Actual

The moment the message lands, the balance card drops below it:

```
after /billing.balance: ["msg:You have 6 open issues…","card:reco","card:balance"]
after the chat turn:    ["msg:You have 6 open issues…","card:reco","msg:reply with the word ping 11:31 ","card:balance","msg:Reasoning complete › Reasoning "]
after reload:           ["msg:You have 6 open issues…","card:reco","msg:reply with the word ping 11:31 ","card:balance","msg:› Reasoning ping 11:31 PM"]
```

The wrong order is not a render race — it survives the reload, so the persisted
ordinals are wrong.

## Root cause

The two transcript entry kinds number themselves on different counters.

- A card takes `nextTranscriptOrdinal()`, the max over messages **and** cards —
  `apps/ui/src/mainview/state/AppController.ts:864`.
- A message takes `nextOrdinal(collections.messages)`, the max over **messages
  only** — `apps/ui/src/mainview/state/AppStore.ts:460` and the sibling
  `message`-producing dispatches at 481, 517, 551, 599, 771, 1308.

The merged transcript sorts on `ordinal` alone
(`apps/ui/src/mainview/state/AppStore.ts:405`). With the opening digest at
ordinal 0 and the reco/balance cards at 1 and 2, a new user message is numbered
`max(messages) + 1 = 1` and therefore sorts above the balance card. Every
message posted after any card is numbered as if the cards did not exist.
