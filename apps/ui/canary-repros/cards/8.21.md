# 8.21 — the keys card has no route to read

- **Origin:** https://canary.smithers.sh (bundle `/assets/index-BHHXuMoZ.js`)
- **Account:** `codeplanesmithers`
- **Repro:** `bun apps/ui/canary-repros/cards/8.21.ts`
- **Screenshot:** `/tmp/canary-cards-8.21-keys.png`
- **Route:** `GET /api/user/byok-keys`

## Steps

1. Open https://canary.smithers.sh signed in.
2. Run `/keys.list`.

## Expected

A `keys` card listing the masked BYOK provider keys (empty state if there are
none).

## Actual

No `keys` card is produced. The transcript reads:

```
/keys.list didn't run
404 page not found
```

`GET /api/user/byok-keys` answers `HTTP 404` with the plain-text body
`404 page not found\n` — the assets binding's not-found page, i.e. the request
fell through the Worker entirely.

## Root cause

`KeysSeam` reads `BYOK_KEYS_PATH = "/api/user/byok-keys"`
(`apps/ui/src/mainview/state/seams/KeysSeam.ts:16`), but the product Worker
implements no `/api/user/*` route at all — `apps/server/src/index.ts` imports
its route constants from `smithers-shared/AgentApiRoutes` and none of them is a
user/BYOK route. `wrangler.jsonc` sends `/api/*` to the Worker first
(`run_worker_first`), so an unhandled `/api/user/...` falls through to the SPA
assets and returns the assets 404. There is no deployment on which this card can
render; this is a missing route, not missing fixture state.
