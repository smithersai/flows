## 2a. Deterministic affordances never route through the model (will's ruling, 2026-08-09)
Observed live: the "Connect GitHub" suggestion pill sent the literal string "Help me connect GitHub" to the LLM, which reasoned, listed commands, SAID "Action: auth.sign-in — I'll run that now" — and ran nothing. Two laws, now enforced in code:
- **Pills and buttons are command BINDINGS** (multi SPEC: "pills alone must complete it with zero AI"). Every suggestion pill binds to a command invoked directly on click/Enter — never a prompt string to the model. "Connect GitHub" resolves by state: signed-out → `auth.sign-in` (the full-page redirect, immediately); signed-in → the repos chooser (`repos.watch`). Audit EVERY pill and kill the prompt-string pattern (`prompt:` pills are banned); the parity gate gains a rule: a pill carrying free text for the model is a violation unless it is explicitly a composer-prefill affordance and says so.
- **Announce = invoke (live failure, will 2026-08-09):** asked to list issues on a named repo with no connector, the model replied "I'll trigger the connection prompt now — just confirm the repo when the UI appears" and invoked NOTHING; no UI appeared. The law: the model never announces an action without the corresponding tool call in the same turn — and agent-invocable interactive commands actually render their card when the agent calls them. Concretely: `connect` / `repos.watch` invoked by the agent (with an optional repo argument — `connect smithersai/smithers` pre-selects it) renders the chooser card in the transcript immediately; the card IS the prompt; the user's only act is the choice that is genuinely theirs. Enforce both ends: the system prompt instructs act-don't-narrate (announcing without invoking is a truth-bar violation), and the tool-loop test double proves the journey: user asks for issues on a named unconnected repo → the model's turn contains the connect tool call → the pre-targeted chooser card renders → confirm → the original ask proceeds.
- **The trigger axis (multi SPEC §1.2a):** the registry gains `trigger: user | agent | both`. Browser-mechanics commands — `auth.sign-in`, `auth.sign-out`, `reset`, `theme`, `chat.stop`, `send` — are `user`-only: they never appear in the agent's tool catalog, so the model can neither invoke nor promise them. The agent tool projection filters by trigger; tests pin that the agent catalog contains no user-only command and that the model asking for one gets an honest tool-result error naming the visible alternative ("sign-in is a button the human clicks").
